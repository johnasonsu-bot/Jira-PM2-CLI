# MCP 接入安全检查

日期：2026-09-07。范围：新增 Python MCP stdio 适配器、工作量排名与 Backend 边界；不是全系统生产安全认证。语言/依赖：Python、官方 MCP SDK 1.x、现有 HTTP API。独立代码复核未发现阻塞性正确性或安全问题。

## 结果与边界

- 新模块未检出常见密钥格式和 eval/exec/Shell/反序列化执行入口。未安装 agt、gitleaks 或 detect-secrets，因此使用范围受控的静态扫描，不声称扫描能保证不存在所有秘密。
- 五个工具固定映射到查询函数，输入由 SDK 类型校验及项目/范围验证处理；不接收 SQL、Shell、文件路径或通用 action。只读限制不依赖模型遵守提示。
- Backend 只接受回环 HTTP 地址，禁用代理和重定向；连接有 15 秒超时。stdio 不新增监听端口。未知工具、无效范围与离线错误均经过真实 MCP 测试。
- 真实 MCP 测试前后任务及审计一致；真实 Codex 验收还核对了现有项目状态哈希，未发生数据变更。

## 剩余发现

| 级别 | 发现 | 建议 |
| --- | --- | --- |
| 中 | 没有多用户身份鉴别或项目授权；同一 OS 用户可访问本机数据 | 保持可信本机单用户使用；远程化前另行设计认证授权 |
| 中 | 项目依赖使用版本范围，没有完整依赖锁文件 | 生产分发前生成平台锁与哈希，并单独进行依赖漏洞审计 |
| 低 | 查询未写入业务审计，只在 Codex 中保留调用证据 | 需要组织审计时增加独立只读访问日志，避免记录正文/秘密 |
| 信息 | 任务正文与项目描述进入 Codex 模型上下文，属于潜在间接提示注入数据 | 客户端继续遵守数据/指令边界；敏感环境按数据策略使用 |
| 信息 | SDK 1.x 为维护线，本机解析为 1.29.1；尚未逐一核查所有依赖发布日期及 CVE | 升级前执行兼容测试，维护依赖审计与补丁计划 |

没有插件 manifest、策略引擎、向量记忆或代理间协作协议，因此相关专用检查不适用。已有 PM2 原型控制台的安全边界见根 README，不通过本 MCP 暴露其命令能力。

## 提示词检查

服务指令明确了角色/能力边界、业务文字不得改变目标和间接注入隔离（3/12，按通用提示词清单计 F）。未在该短提示中单独实现内部信息泄露、输出链限制、多语言、Unicode、上下文溢出、社会工程、危险输出、速率认证及内容校验等九项专项提示规则。该机械评分不表示工具具备这些危险能力，也不能替代代码级控制；本适配层不是独立 LLM 代理，依赖 Codex 的上层安全控制，并用只读代码边界缩小后果。不得据此宣称生产环境已全面合规。
